# JDX 0.3.0

京东 iOS 广告与推荐位置管理插件。本次修复已确认的设置入口识别遗漏、关闭规则却仍在启动或检查时安装业务方法、旧版全部拦截配置导致正常推荐被隐藏等问题，并增加不安装业务 Hook 的纯净启动模式。

**全局联网失败仍待真机对照。** 上传的 0.2.1 诊断报告能确认入口探测和配置问题，但没有请求错误码或服务端响应，不能证明搜索、购物车、订单、客服和视频页的失败来自同一原因。本版首先提供可直接进入设置、可恢复配置、可确认业务方法替换数量的对照环境；不宣称已经修复服务器、账号或全部网络问题。

## 安装与首次启动

1. IPA 注入使用 **JDX.dylib**；Rootless 越狱使用 **com.solhk.jdx_0.3.0_iphoneos-arm64.deb**。
2. 替换时先移除旧 JDX / JDAdBlock 动态库或旧安装包，再加入新版并重新签名／安装。不要同时注入两个版本。
3. 从多任务界面划掉京东，再重新打开。**首次安装或从旧配置升级，默认进入纯净模式：本次进程不安装任何 JDX 业务 Hook。** 设置入口、日志和被动系统网络路径观测仍可使用。
4. 先检查搜索、购物车、订单、客服与“逛”页。如果纯净模式下正常，再打开 JDX，保持或恢复推荐配置，关闭 **「纯净模式（重启生效）」**，然后再次彻底退出并重开京东。
5. 重开后按总开关与各位置选择执行拦截。如果原总开关已关闭，可开启 **「启用 JDX 拦截」**。建议先用推荐配置，再逐项尝试搜索过滤和普通推荐隐藏。

如果纯净启动后仍出现同样错误，请在此状态下复现并导出诊断。报告应显示 `session_safe_mode=true`、`business_hooks_installed=0`；这表示 JDX 未替换业务方法，不能仅据此判定京东服务、账号、重签名环境或其他插件正常。

- 最低 iOS 15.0，arm64。业务适配沿用已分析的版本字段组合 **171204 / 16.1.83**，也接受这两个字段交换顺序。其他版本保留设置与诊断入口，跳过业务方法替换。
- 包标识为 `com.360buy.jdmobile`、其双开后缀，或主程序名称为 `JD4iPhone` 时可启动插件；业务规则仍受版本、开关和方法签名校验约束。
- [GitHub Actions 构建记录与下载](https://github.com/SOLHK/JDX/actions/workflows/build.yml)：打开对应提交的成功运行，在 Artifacts 下载 `JDX-arm64-提交号`。包内含 dylib、deb、`SHA256SUMS` 与 `build-manifest.json`。

## 打开设置

**进入京东「我的 → 设置」，点击「JDX」或「JDX 设置」入口。** 本版通过可见视图的 responder 链发现实际页面，补充对自定义容器和顶部固定设置标题的识别，避免仅停在 `JDTabBarController`。

普通应用页面的屏幕边缘还提供可拖动的 **JDX 备用按钮**，可单指打开插件设置，拖动位置会保存。设置页入口位置冲突时也可使用该备用按钮。键盘、系统弹窗、分享或文件／图片选择界面、本插件面板显示时，以及应用不活跃时，备用按钮会隐藏，返回后恢复。双指长按约一秒仍保留为备用手势。纯净模式、总开关关闭或宿主版本不兼容时，设置入口仍可使用。

入口不修改京东设置列表的数据源，也不替换通用 `UIViewController` 生命周期方法。对自绘导航的辅助识别仅匹配顶部固定设置标题，不持久化或导出页面文字。具体显示与避让仍需在真机页面验证。

## 纯净模式、总开关和配置迁移

| 操作／状态 | 业务方法行为 |
| --- | --- |
| 以纯净模式启动 | 本次进程不安装业务 Hook；设置、日志与系统路径观测可用 |
| 纯净会话中关闭纯净模式 | 保存下次启动选择；当前会话仍不安装，必须彻底退出并重开 |
| 普通会话中开启纯净模式 | 已有包装器立即透传；重开后才成为零业务 Hook 的纯净会话 |
| 普通会话中关闭总开关 | 立即暂停过滤，保留各项选择；已安装的包装器仍存在 |
| 总开关关闭后重新启动 | 不安装业务 Hook；普通会话中再次开启总开关时可按选择安装 |
| 普通会话中单项关闭 | 该项透传；冷启动时关闭的规则不安装，也不消耗延迟加载重试次数 |
| 运行诊断或导出日志 | 只读取当前状态，不安装或重装业务 Hook |

本次启动模式与下次启动选择分别记录，切换后界面会提示是否需要重启。在纯净会话中选择“全部拦截”、切换位置或关闭再开启总开关，都不会绕过本次会话的纯净状态。

**配置升级只执行一次：** 旧配置 schema 2 且 14 项全部开启时，恢复为推荐配置，并备份原总开关和 14 项布尔值。其他自定义选择保持不变，已有总开关选择也保留。首次升级启用纯净模式；后续启动保留用户保存的模式，不反复重置。

- **单项开启＝拦截，关闭＝保留。** 设置自动保存；实际拦截还要求本次会话与当前选择均为非纯净模式、总开关开启且版本匹配。已有结果可能需要刷新或重新进入页面。
- **恢复推荐配置**：保留正常商品推荐与搜索内容，只选择开屏和已识别的首页推广位置。
- **所有位置：全部拦截／全部保留**：一次设置全部细项。“全部拦截”包含正常商品推荐区域，可能造成留白。
- **暂时恢复京东原样**：关闭总开关并保留细项选择，是当前会话的透传对照。若要确认完全不安装业务方法，请使用纯净模式并重启。

## 14 个独立开关

下表是推荐配置的选择。纯净模式下所有业务拦截均暂停，即使某个开关显示开启。

| 位置 | 推荐配置 | 说明 |
| --- | --- | --- |
| 开屏广告 | 拦截 | 已识别的开屏展示判断 |
| 首页顶部动图推广 | 拦截 | 保留搜索栏与频道导航 |
| 首页普通悬浮卡 | 拦截 | 普通悬浮样式 |
| 首页 9:16 悬浮卡 | 拦截 | 9:16 悬浮样式 |
| 首页双屏悬浮卡 | 拦截 | 双屏悬浮样式 |
| 首页底部广告横幅 | 拦截 | 使用广告标记，保留已知奖励／功能引导；元数据不足时放行 |
| 首页底部所有横幅 | 保留 | 包括奖励／功能引导；独立于上一项，并优先处理 |
| 首页商品推荐流 | 保留 | 开启会隐藏正常商品推荐，可能导致首页中部留白 |
| 搜索付费商品卡 | 保留 | 列表、网格广告配对且结构符合预期时才过滤 |
| 搜索顶部店铺广告 | 保留 | `adShop` / `adSlideShop` |
| 搜索列表店铺广告条 | 保留 | 两种已识别店铺广告条 |
| 搜索尾部推荐 | 保留 | 推荐分页独立控制 |
| “我的”页商品推荐 | 保留 | 不处理订单或账户信息 |
| 商品详情底部推荐 | 保留 | 原生详情推荐楼层 |

这些开关覆盖本项目已经识别的广告／推荐位置，不代表已识别京东所有 H5、活动页或新版本广告。

## 日志导出与增强诊断

1. 打开 JDX，先确认本次启动模式和已安装业务方法数量，开启 **增强诊断**。
2. 关闭设置，重现搜索、购物车、订单、客服或其他页面的问题。
3. 再次打开 JDX，选择 **标记刚才出现的问题**，记录问题类型与时间。
4. 选择 **导出日志与诊断包**，通过系统分享面板保存 JSON。
5. 对比纯净模式与启用推荐配置后的行为时，分别按对应模式彻底重启、复现并导出。

诊断包含：

- 插件、系统和宿主版本，总开关、各位置选择、当前／下次启动模式、待重启状态及配置迁移记录。
- 15 个业务方法的匹配、实际类型编码、方法归属、安装状态，以及当前入口是否仍与 JDX 实现匹配。
- 实际已安装业务方法数量与启用状态；方法被其他实现覆盖／包裹的记录只是线索，不能单凭它确认冲突。
- 规则命中、放行、结构异常、过滤保护的计数，以及增强模式下的有限调用样本、前台页面类名变化和手动问题标记。
- 设置入口的探测与显示状态，相关动态库文件名，以及日志写入、限额和导出状态。
- 系统 Network 路径状态和 Wi-Fi／蜂窝等固定元数据。

### 系统路径不等于京东服务连通

本版使用 Network 框架的被动路径监测，不发起探测请求、不替换京东网络实现。`network_path.status=satisfied` 仅表示系统存在可用网络路径，**不表示京东接口请求成功，也不证明账号、DNS 查询、代理转发或服务端正常**。报告始终明确记录 `service_connectivity=not_tested`。

记录项仅有路径状态、接口类型布尔值、DNS／IPv4／IPv6 支持标记、受限／高成本网络标记及固定错误原因代码。不枚举网络接口名称、网关或 IP 地址。

### 隐私与限额

日志不包含网络 URL、请求／响应正文、Cookie、token、账号、订单、收货地址、IP 地址、页面文字或异常 reason，也不自动上传。设置识别只临时比较顶部固定标题，既不持久化该文字，也不将其写入报告。配置迁移备份只保存本插件的开关值。

本地日志每文件最多 256 KiB，共 3 份；内存最近 300 条；导出缓存最多 3 份。增强采样最多每秒 20 条、5000 条或 10 分钟，达到限制自动停止。规则累计计数保留，磁盘写入及导出在后台队列执行。“清空历史日志”只清理本插件历史与导出缓存，保留配置和当前适配状态。

## 保留的拦截保护

- 方法安装核对归属：继承方法只在目标类添加覆盖，不改写父类 Method。
- 安装前保存原 IMP，严格校验完整类型编码；未知方法、签名不匹配、重复安装或安装失败时跳过。
- 包装器保留原调用链；总开关、纯净模式选择和独立开关在调用时读取。
- 首页推荐高度与视图两方法都就绪才执行该组隐藏。
- 搜索过滤不修改输入字典、数组或模型；双布局配对异常、getter 异常或过滤将清空结果时返回原结果。
- 已隐藏视图在规则停用时恢复其保存的 `hidden` 状态；缓存布局与被过滤的结果仍可能需要宿主重新生成。

## 构建与测试

### macOS / Xcode

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 build.py --toolchain xcode --build-dir build --output dist
```

GitHub Actions 配置了原生 Foundation 搜索、配置、诊断和设置页发现测试，并执行 arm64 编译与 Apple `codesign` 校验。新增测试和构建是否通过，以 **0.3.0 对应提交**的 Actions 结果为准。

### Linux / Windows / LLVM

需要能生成 arm64 Mach-O 的 clang、ld64.lld 和 iPhoneOS SDK。SDK 版本从 SDKSettings 读取；不能读取时可传 `--sdk-version`。

```sh
python3 build.py --llvm-dir /path/to/llvm/bin --sdk /path/to/iPhoneOS.sdk --build-dir build --output dist
```

Windows 的 `--llvm-dir` 可使用 `C:/Program Files/LLVM/bin`，脚本自动处理 `.exe`。构建链接系统 Foundation、UIKit、CoreFoundation 和 Network 框架；打包无需额外工具。产物校验包括 Mach-O 平台／架构／依赖、ad-hoc SHA-256 签名页、rootless 安装目录／权限及编译前后源码一致性。`build-manifest.json` 保留源文件哈希，`SHA256SUMS` 保留产物摘要。

本仓库不包含京东 IPA、SDK、账号信息或真机抓包。自动测试与静态分析不能替代真机注入、设置入口展示及实际业务流程验证。
