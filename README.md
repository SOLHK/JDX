# JDX 0.2.1

京东 iOS 广告与推荐位置管理插件。此版针对 0.1 启用后首页大片空白、其他页面异常难以定位的问题，重写方法安装与开关机制，并加入可导出的本地诊断。

**这是需要真机复核的修复测试版。** 已修正可由源码确认的首页推荐误隐藏和继承方法越界替换风险；购物车、订单、搜索及视频页截图中的错误，不能仅凭截图认定是同一种网络故障。

## 安装

- IPA 注入使用 **JDX.dylib**；Rootless 越狱使用 **com.solhk.jdx_0.2.1_iphoneos-arm64.deb**。
- 替换旧版本时，先移除旧 JDX / JDAdBlock 动态库或旧安装包，避免两个版本一起加载。再加入新版，重新签名／安装，并彻底结束京东进程后重新打开。
- 最低 iOS 15.0，arm64。广告适配沿用已分析的版本字段组合 **171204 / 16.1.83**，也接受这两个字段交换顺序。其他版本保留设置与诊断入口，跳过业务方法替换。
- 包标识为 com.360buy.jdmobile、其双开后缀，或主程序名称 JD4iPhone 时可启动插件；是否执行规则仍以版本和每个方法签名校验为准。

[GitHub Actions 构建记录与下载](https://github.com/SOLHK/JDX/actions/workflows/build.yml)

打开成功运行，在 Artifacts 下载 JDX-arm64-提交号。包中包含 dylib、deb、SHA256SUMS 与 build-manifest.json。不要继续使用 0.1 的旧下载。

## 打开设置

**京东「我的 → 设置」→ 点击右上角「JDX」**，即可单指打开插件设置，不用在紧凑页面双指长按。没有标准导航栏的已识别京东设置页会显示「JDX 设置」小按钮。双指长按约一秒仍然保留为备用入口。

识别基于可见页面的精确标题及保守的控制器类名判断，不修改京东设置列表数据源，也不覆盖原有按钮。部分京东版本可能采用不同的标题或自绘导航，需要根据实际版本截图或 IPA 单独适配。支持 UIScene 与旧式应用窗口。

- **总开关关闭**：所有业务拦截调用京东原方法并原样返回，设置与诊断仍可使用。各位置的选择保留。
- **单项开启＝拦截；关闭＝保留。** 修改自动保存，后续方法调用读取新设置。已有结果需要刷新或重新进入页面；视图隐藏能恢复，但已被过滤的模型需要宿主重新生成。
- **恢复推荐配置**：保留正常商品推荐与搜索内容，只开启开屏和已识别的首页推广位置。
- **所有位置：全部拦截／全部保留**：一次设置全部细项。“全部拦截”也会移除正常商品推荐区，因此首页出现留白可能是所选配置的结果。
- **暂时恢复京东原样**：关闭总开关，适合对照复现，不丢失单项选择。

从 0.1 升级时沿用已有总开关选择；新增细项以推荐配置初始化。后续启动保留用户选择。

## 14 个独立开关

| 位置 | 推荐配置 | 说明 |
| --- | --- | --- |
| 开屏广告 | 拦截 | 已识别的开屏展示判断 |
| 首页顶部动图推广 | 拦截 | 保留搜索栏与频道导航 |
| 首页普通悬浮卡 | 拦截 | 普通悬浮样式 |
| 首页 9:16 悬浮卡 | 拦截 | 9:16 悬浮样式 |
| 首页双屏悬浮卡 | 拦截 | 双屏悬浮样式 |
| 首页底部广告横幅 | 拦截 | 使用广告标记，保留已知奖励／功能引导；元数据不足时放行 |
| 首页底部所有横幅 | 保留 | 开启后整个位置都拦截，包括奖励／功能引导；优先于上一项 |
| 首页商品推荐流 | 保留 | 开启会隐藏正常商品推荐，可能导致首页中部留白 |
| 搜索付费商品卡 | 保留 | 列表、网格广告配对且结构符合预期时才过滤 |
| 搜索顶部店铺广告 | 保留 | adShop / adSlideShop |
| 搜索列表店铺广告条 | 保留 | 两种已识别店铺广告条 |
| 搜索尾部推荐 | 保留 | 推荐分页独立控制 |
| “我的”页商品推荐 | 保留 | 不处理订单或账户信息 |
| 商品详情底部推荐 | 保留 | 原生详情推荐楼层 |

这些开关覆盖本项目已经识别的广告／推荐位置，不代表已识别京东所有 H5、活动页或新版本广告。搜索过滤等默认保留的项可在基础页面正常后逐项打开对比。

## 日志导出与增强诊断

1. 打开设置，开启 **增强诊断**。
2. 关闭设置，重现首页、搜索、购物车、订单或“逛”页的问题。
3. 再次打开设置，选择 **标记刚才出现的问题**，记录问题类型与时间。
4. 选择 **导出日志与诊断包**，在系统分享面板保存或发送 JSON。
5. 如需对照，关闭总开关，刷新或重新进入相同页面，再标记并导出一次。

“运行检查并查看诊断”会检查并展示：

- 插件、系统和宿主版本，以及总开关和每项配置。
- 15 个业务方法的匹配、实际方法拥有类、完整 ABI 编码与安装状态。
- 方法是否被后加载的其他实现覆盖／包裹；此状态是线索，不等于确定发生冲突。
- 规则命中、放行、结构异常、过滤保护的累计计数。
- 增强模式下的有限调用样本、前台页面类名变化和手动复现标记。
- 已加载的 JDX、JDAdBlock 与常见加载器文件名，辅助查找重复安装。
- 日志限额、丢弃计数、磁盘写入错误及导出状态。

日志不包含网络 URL、请求／响应正文、Cookie、token、账号、订单、收货地址、页面文字或异常 reason，也不自动上传。没有更改网络栈、证书校验、购物车、订单或支付接口；报告本身不能证明网络故障的服务端原因。

本地日志每文件最多 256 KiB，共 3 份；内存最近 300 条；导出缓存最多 3 份。增强采样最多每秒 20 条、5000 条或 10 分钟，达到限制自动停止。规则累计计数保留，文件写入及导出在后台队列执行。“清空历史日志”仅清理本插件历史与导出缓存，保留配置和当前适配状态。

## 修复要点

- 所有方法替换都确认归属。继承的方法只在目标类添加覆盖，不再改写父类 Method，避免影响兄弟页面。
- 安装前发布原 IMP，严格校验完整类型编码；方法不存在、不兼容、重复安装或覆盖失败时跳过，不扩大 Hook 范围。
- 每个替换保留原调用链；总开关和独立开关在调用时读取，不再只在进程启动时判断。
- 首页正常推荐不再默认关闭；首页高度与视图两个方法都就绪才执行该组隐藏。
- 搜索过滤不修改原字典、数组和模型。双布局数量、广告标记、配对关系异常或 getter 抛异常时完整返回原结果；会把整个结果清空时同样放行。
- 设置入口独立于业务页面；「我的 → 设置」提供单击入口，保留京东其他设置按钮；无标准导航栏时使用备用小按钮，不再 Hook UIViewController / “我的”页的 viewDidLoad。
- 已隐藏的视图在关闭对应规则时恢复原 hidden 状态；缓存布局及已移除结果仍需要页面刷新。

## 构建与测试

### macOS / Xcode

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 build.py --toolchain xcode --build-dir build --output dist
```

GitHub Actions 还会在 macOS 运行 Foundation 原生搜索、配置和诊断测试，并执行 Apple codesign 校验。

### Linux / Windows / LLVM

需要能生成 arm64 Mach-O 的 clang、ld64.lld 和 iPhoneOS SDK。SDK 版本从 SDKSettings 读取；不能读取时可以传 --sdk-version。

```sh
python3 build.py --llvm-dir /path/to/llvm/bin --sdk /path/to/iPhoneOS.sdk --build-dir build --output dist
```

Windows 的 --llvm-dir 可使用 C:/Program Files/LLVM/bin。脚本自动处理 .exe；无需额外打包工具。产物校验包括 Mach-O 平台／架构／依赖、ad-hoc SHA-256 签名页、rootless 安装目录／权限、编译前后源码一致性。编译清单保留源文件哈希，便于确认收到的二进制对应哪版代码。

本仓库不包含京东 IPA、SDK、账号信息或真机抓包。自动测试和静态分析不能替代真机注入、页面展示及下单流程验证。
