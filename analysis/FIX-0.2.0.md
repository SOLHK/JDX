# 0.2.0 修复与验证记录

## 输入与结论边界

输入为 SOLHK/JDX 的 0.1 源码（基线提交 61500f77e74976b7c0600a5102e51c0f5dbfb293）以及用户提供的首页、搜索、购物车、订单、视频等页面异常截图。本次没有收到对应真机日志、新 IPA 或可运行的京东设备。

可直接从源码确认：

1. 总开关默认开启时，旧代码将首页推荐高度设为 0，并隐藏整个 bottomCollectionView。首页正常推荐空白是该默认策略能直接造成的效果。
2. 旧 FindMethod 使用 class_getInstanceMethod 获取方法，随后直接 method_setImplementation。前者会搜索父类；若获取的是继承方法，后者会修改父类方法。该风险已通过运行时模拟复现，但没有现场运行时数据证明用户各个报错页面具体由哪一次继承方法替换触发。
3. 旧代码没有购物车、订单、网络栈、证书或支付接口拦截。截图上的“网络连接已断开”“当前访问人数过多”不能直接等同于网络真的中断，也不能证明唯一根因。

运行时语义依据：[Apple class_getInstanceMethod](https://developer.apple.com/documentation/objectivec/class_getinstancemethod(_:_:)) 与 [Apple class_addMethod](https://developer.apple.com/documentation/objectivec/class_addmethod(_:_:_:_:))。

## 实现

- JDXHookRuntime.h：核对方法完整编码与真正拥有类；只修改目标类自己拥有的方法，继承方法通过 class_addMethod 建立覆盖；在替换之前保存原始实现；重复安装以及第三方包裹后的复挂均拒绝。
- JDXConfig：14 项独立配置、总开关、推荐／全开／全保留配置；默认保留首页等普通推荐及搜索模型；保留旧总开关。
- Tweak：15 个已识别业务方法，每个包装器调用原实现，按当前配置决定是否拦截；首页推荐组两方法均就绪才隐藏；元数据缺失时保守放行。
- JDXSearchFilter：只处理已知产品与 VM；完整校验两种布局的数量与广告配对；不修改输入；未知结构、异常 getter 或过滤后为空时返回原结果。
- JDXSettings：窗口双指长按入口，兼容 UIScene 与旧式窗口生命周期；主线程呈现、后台导出；导出期间阻止并发表格弹窗抢占分享。
- JDXDiagnostics：有界日志、命中计数、方法适配、前台页面类名、复现标记、重复插件线索及 JSON 导出；固定元数据过滤；不 hook 网络与异常处理器。

## 自动检查

### 可在 Linux 本地运行

- Python 构建完整性测试：校验 Mach-O 架构／平台、非系统依赖拒绝、签名页篡改、Debian 包内容和权限、SDK 元数据及工具链路径处理。
- C 运行时模拟：旧版继承污染复现，目标类隔离，保留父类与兄弟类实现，原始 IMP 发布顺序，重复安装和间接递归防护，未知类／方法／签名、安装失败时放行。
- iPhoneOS SDK 下严格 arm64 编译、链接、Clang 静态分析及真实产物验证。

### macOS 原生 Foundation 检查

CI 运行生产实现，而非对源码做字符串匹配：

- 搜索：11 组场景，包含完整回滚、布局配对、排序、输入不变、未知模型与异常 getter。
- 诊断：隐私 canary、并发计数、有界日志轮转、合法 JSON 导出、清除并发、导出缓存容量及系统时间倒退。
- 配置：推荐默认、旧偏好迁移、独立开关、总开关、批量配置、重读持久配置及未知版本放行。

实际执行结果以对应提交的 GitHub Actions 日志为准。build-manifest.json 保存编译版本、SDK 与源文件哈希；SHA256SUMS 保存产物摘要。
